# CONVENTIONS.md — code and repo conventions

## Python

- Stdlib-only in `harness.py`. No new third-party dependencies without an
  experiment-driven reason, stated in the commit.
- Keep the harness a single file until it genuinely doesn't fit; the
  one-file shape makes the control/experimental symmetry auditable.
- Phase-1's minimalism is load-bearing: no taxonomy, clustering,
  templates, or AST normalization in the phase-1 path. New machinery goes
  behind a flag or in a new module.

## Data

- `runs/` is **curated**: `RESULTS-*.md` summaries, the primary run log,
  and the learned store for a completed phase. Scratch runs, 0-byte
  stores, and superseded logs stay local — don't commit them.
- Store JSONL schema is append-only. Schema changes bump the phase and
  start a new store; never rewrite a committed store's history.

## Fixtures

- Fixtures are regenerated by hand and committed clean. Mutations happen
  only through the harness's `setup` functions at run time.
- Never hand-edit fixture sources to make a task pass. If a baseline is
  wrong, fix the baseline in its own commit and re-run.

## Commits

- One logical change per commit; imperative subject line
  (`Add AST normalization behind --normalize`).
- Security-relevant changes (blocklist, timeouts, cwd handling) say so in
  the message and reference SECURITY.md.
- Result claims in commit messages must match `runs/RESULTS-*.md`.

## Docs

- `.agents/` docs are normative for agent contributors. If the code and a
  doc disagree, fix the code or the doc in the same change — never leave
  them disagreeing.
- Mark speculation as speculation. Measured numbers go in `runs/`;
  expectations go in ROADMAP.md labeled as such.
